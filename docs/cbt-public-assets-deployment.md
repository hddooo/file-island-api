# CBT 공개 원본 자산 주소와 준비 상태

공개 대상은 사용자가 공개를 승인한70~79회 원본 문제500개와72회 공통 자료1개다. 정답·채점키·개인 기록은 공개하지 않는다. 새 호스팅·유료 디스크나 데이터 이관이 필요한 변경이 아니다.

## 현재 자산 주소

기본 원본 URL은 `https://study.fileisland.co.kr/media/cbt-originals`다. 2026-11-06 공개 manifest와501개 파일의 WebP·SHA256를 읽기 전용으로 확인했다. 이전 기본값 `https://hanq.vercel.app/media/cbt-originals`는 manifest 요청에404를 반환하므로, 별도 설정 없이 이 주소를 사용하는 서버는 준비 완료로 판정할 수 없다.

`HANQ_CBT_PUBLIC_ASSET_BASE_URL`에 명시한 주소는 기본값보다 우선한다. 빈 값은 현재 기본값을 사용하고, `off`는 공개 원본을 끈다. 유효한 기존 비공개 자산 디렉터리도 유지한다. 코드의 기본값만 바꾸어도 운영 환경에 명시된 옛 주소가 자동 교체되는 것은 아니다. HTTPS·URL 자격증명/쿼리 금지·리다이렉트 금지·크기/시간 제한과 무결성 검사는 그대로 유지한다.

## 준비 판정

- 인증된 `GET /api/v1/cbt/rounds`는 문항 카탈로그와 manifest 등록 상태를 확인하며 목록에서501장 이미지 바이트를 내려받지 않는다.
- 각 회차는3초 확인 예산 안에서 `ready`, `check-delayed`, `assets-pending`, `catalog-pending` 상태를 독립적으로 반환한다. `GET /api/v1/cbt/rounds/:round`는 해당 회차를 재확인한다.
- 시험 시작 시에는 공통 자료를 포함한 그 회차의 전체 이미지 WebP·크기·SHA256를 검사한다. 실패하면 시계를 시작하지 않는다. 목록의 등록 상태만으로 시작 검사를 생략하지 않는다.
- 준비 상태 조회는 시험·답안·기록을 생성하거나 초기화하지 않는다. 인증·소유권·정답/채점 계약과 사용자 데이터는 바꾸지 않는다.

## 운영 반영과 검증의 구분

현재 `file-island-api`의 main CI는 빌드 전용이다. 이미지 workflow도 운영 배포 자격이 없는 산출물을 만든다. 운영 Windows 홈서버의 기존 검토된 controller/bootstrap·mount·정확 schema/checksum·복구 계약을 사용해야 한다. 단순 main push, 이미지 생성 또는 다른 경로의 `npm start`를 운영 적용 성공으로 간주하지 않는다. 관련 계약은 [저장소 이관 기록](repository-migration.md)과 기존 운영 인계 문서를 따른다.

운영 담당자는 기존 권한으로 실제 프로세스의 자산 base host/path만 확인하고 비밀값·DB 연결주소·사용자 토큰을 출력하지 않는다. 명시적인 옛 주소가 있으면 기존 설정 관리 경로에서 해당 일반 자산 URL만 바로잡아야 한다. 그 뒤 기존 배포/재적용 계약으로 정확 코드와 설정을 적용하고, 인증된 rounds 읽기 응답에서70~79회 상태를 확인한다. 검수용 시험 시작·답안 제출·seed·원장 보정은 이 절차에 포함하지 않는다.

이번 기본값 변경은 DB migration이나 사용자 데이터 변경을 요구하지 않는다. 실제 운영 override와 인증된 rounds 응답은 클라우드 읽기 경로에서 아직 확인하지 못했다. 공개 자산 정상·단위 테스트·main 빌드 성공과 운영 준비 완료를 구분해 보고한다.
