# Member-shared TOEIC content, private practice

The existing `toeic_member_notebook` singleton explicitly selects the content publisher. No user is automatically enrolled and no contents or user rows are copied. When absent, existing private behavior is preserved.

Authenticated notebook and legacy grammar reads already use this publisher. Practice catalog, collection study, images and audio now resolve the same publisher. Catalog display numbers and original-wrong pool come from that source; personal results do not change another member's playlist. Answers, latest outcomes, history, growth and word checks retain the authenticated viewer as owner. Published-source wrong reports are provenance (`originalWrong`), not another member's personal attempts. Other members cannot edit/merge/archive the publisher's notes, and old private contents and histories are retained.

Migration041 changes only the practice-answer reference: the source collection and authenticated learner can differ. Existing immutable records are not rewritten. The user/source foreign keys and an INSERT trigger restrict sources to the viewer's own or explicitly published content; unknown private collections remain inaccessible. Batch exam runs remain private and unchanged. JWT guards, binary relay allowlist/limits, no-store, authentication and 90-day session behavior are unchanged.

Activation requires an explicit, verified publisher ID and is a separate operational action on the existing singleton. Do not hardcode an email/ID in startup or seed demo rows. Apply041 before activation. Check the currently selected source and preserve existing state; do not silently replace a different publisher. Turning off publication removes only the singleton configuration after coordination; it does not delete content or any learner history. Existing answers continue to resolve source metadata from the learner's own immutable events.

Tests: unit regressions plus integration/toeic-member-learning.test.ts; isolated real-SQL/HTTP verification additionally covers three synthetic accounts, identical source IDs/catalog/audio/notes, private answers/history/checks, anonymous rejection, foreign assets and canonical edit rejection. No real account submissions are needed. Grammar/print content uses the common note list; checked-only views remain individual study preferences.
