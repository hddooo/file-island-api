# CBT 회차 확인과 성장 점수 하한

회차 목록은 공통 자료를 포함한 문항 카탈로그와 공개 manifest 등록 여부를 확인한다. 공개 원본 이미지 501장을 목록 요청에서 받지 않는다. 각 회차의 3초 확인 예산과 ready / check-delayed / assets-pending / catalog-pending 상태를 분리하고, 인증된 GET /api/v1/cbt/rounds/:round 는 그 회차만 재확인한다. 시작 시 기존 전체 이미지 바이트·SHA256 검증을 통과해야 시계가 시작된다. manifest 등록 후 실제 파일 누락/손상이 생기면 목록은 등록 상태를 보여도 시험 시작은 거부된다.

성장 점수 차감은 기존 사용자 행 잠금과 채점 트랜잭션 안에서 min(요청 차감, 보유 점수)만 반영한다. 일반 풀이, CBT 최종 채점, 오답복습 도전에 적용된다. 실제 차감액을 원장 및 저장 결과에 동일하게 기록하며 제출 재전송은 원래 금액을 반환한다. CBT policyGrowthReward는 기존 점수 구간의 금액, growthReward는 실제 반영 금액이다. 기존 양수 보상·접근 정책·제출 중복 방지·원장 append-only 제약은 유지한다.

015_growth_floor.sql은 INSERT 트리거에서도 사용자 행을 잠그고 원장 합계를 다시 확인한다. 기존 원장 합계가 음수인 계정이 하나라도 있으면 migration을 거부한다. 자동 시작 migration이 따라서 중단될 수 있다. 이 migration은 계정 점수, 과거 원장, 시험 이력을 수정하지 않는다. 기존 음수 계정의 보정은 별도 승인된 감사 가능한 조정안이 필요하다. 운영 적용 전 기존 권한으로 읽기 전용 집계 보고를 확인하고, 앱과 migration을 같은 배포에 포함해야 한다.

검증: 단위 테스트의 실제 로컬 HTTP manifest 지연/재시도, 목록 이미지 다운로드 0회, 10회차 독립 준비 상태, 파일 누락 시 시작 전 거부. 격리된 loopback *_test DB에서 migration, 잔액3점 동시 -5 요청의 -3/0 기록, 재전송, CBT 실제 -3점/50개 채점/단일 원장, 오답복습0점, DB 직접 동시 삽입, 기존 음수 aggregate migration 거부 및 전체 rollback, append-only 거부를 확인했다. 사용자의 운영 DB에는 쓰지 않았다.

운영 진단 한계: 공개 questions 목록에는 70~79회 각각50문항, 공개 manifest에는501파일이 있다. 기존 로컬 코드+기존 configured DB를 READ ONLY로 실행했을 때 14.568초/79·78만 가능이었고, 수정 코드로는4.085초/10회차 모두 가능했다. 이는 해당 코드 경로의 재현과 개선 증거다. 인증된 운영 rounds는401이어서 실제 배포 API 커밋, Render 연결 설정과 해당 계정의 응답은 미확인이다. 운영 로그인 토큰을 추출하거나 새 인증·배포·seed·운영 migration을 수행하지 않았다.

## 배포 전 읽기 전용 점검

기존 배포 대상의 기존 환경·권한에서 `npm run check:growth-floor`를 실행한다. 이 명령은 migration·seed·계정 변경 없이 READ ONLY 트랜잭션에서 음수 원장 합계 개수만 출력한다. 사용자ID·이메일·연결주소·키는 출력하지 않는다. 로컬 `.env` 결과를 Render 결과로 간주하지 말고, 실제 배포 API와 같은 기존 연결 환경에서 실행해야 한다. 권한이 없거나 연결에 실패하면 새 권한을 만들지 말고 점검 불가로 보고한다.

- 종료0 / `status:pass` / `negativeBalances:"0"`: 그 시점에 기존 음수 합계 없음. 배포 직전 재확인한다.
- 종료2 / `status:reconciliation-required`:015가 서버 시작 migration에서 실패한다. 운영 적용 전에 별도 승인된 감사 가능한 조정이 필요하다. 이 명령은 보정하지 않는다.
- 종료1 / `status:unavailable`: 연결·조회 실패로 상태 미확인. 인증정보나 DB 오류 전문은 출력하지 않는다.

점검과 적용 사이 기존 서버가 음수 잔액을 만들 가능성이 있으므로, 최종 보장은015의 트랜잭션 내 guard와 INSERT trigger다. 읽기 전용 점검 통과를 실제 migration 적용 완료로 보고하지 않는다.
