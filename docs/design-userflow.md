# API 사용자 흐름과 접근 범위

화면 흐름의 기준은 [FE 사용자 흐름](https://github.com/blockmonkey1992/hanq/blob/dev/docs/design-userflow.md)이다. 아래는 서버의 상태 전이와 데이터 소유만 기술한다.

- 로그인한 사용자가 게시된 학습 자료를 조회한다. 게시자 콘텐츠와 학습자 답안·정오답·진도·개인 이력은 분리한다. 비로그인 자료 공개나 타 계정 기록 공개로 확대하지 않는다.
- 배틀 입장 → 대기 요청 저장 → 상대 수락 → 준비 상태 고정 → 서버 카운트다운 → 문제/묶음 시작. 미만료 초대는 재접속 시 복구하고 중복 수락은 같은 상태로 조정한다.
- 본인 제출은 서버가 한 번 접수한다. 양쪽 제출 또는 마감에 판정을 공개하며 그 전 정답/해설은 숨긴다. 봇의 답·시간·판정도 재접속 때 재추첨하지 않는다.
- 판정·연출 예산 종료 → 다음 문제 준비/필요시 단절 유예 → 카운트다운. 최초 수동 Ready를 반복 요구하지 않는다. 문제 중 끊겨도 마감은 연장하지 않는다.
- 종료 → 원자적 단일 정산 → 참가자 전용 아카이브. 시작 전 나가기는 무효 취소·XP0, 시작 후 나가기는 도주·패배, 연습전은 결과와 무관하게 XP0이다.
- 본인 history/wrongnotes 조회 → 기존 문제·답·정답·해설 리뷰/재풀이. 새로고침·중복 요청·다른 계정 접근으로 XP 또는 원본 기록이 달라지면 안 된다.

현재 API 경로와 저장 규칙은 [api.md](api.md), [battle-wrongnotes.md](design-development.md#battle), [battle-push.md](design-development.md#battle)를 참조한다. 실제 사용자 계정으로 대결·답안·XP를 만들어 배포 검사하지 않는다.
