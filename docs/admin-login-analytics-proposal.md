# 관리자 로그인 집계 — 통합 전 초안

## 데이터와 계약

`GET /api/v1/ops/login-analytics?days=7` (`7`, `30`만 허용).
기존 JWT 가드와 PortalService의 ADMIN 확인을 그대로 사용한다.
`hanq.member_access_logs`의 `signin`만 집계한다. 이 이벤트는 비밀번호
검증과 사용자 잠금 확인 후 성공 로그인 트랜잭션에서 저장된다.
회원가입과 토큰 갱신은 로그인 횟수에 포함하지 않는다.

`recordedLoginCount`는 기간 내 저장된 성공 로그인 이벤트 수,
`recordedUniqueUsers`는 전체 기간의 DISTINCT user_id 수다.
일별 고유 회원 수를 더해 전체 고유 회원 수로 사용하면 안 된다.
날짜 경계는 Asia/Seoul이며 오늘은 응답의 generatedAt까지 포함한다.
개인별 로그인 메타데이터를 응답에 넣지 않는다.

최초 이벤트는 수집 시작을 증명하지 않는다. coverage는 unverified,
collectionStartedAt는 null이다. 최초 기록 이전 날짜와 기록이 전혀 없는
경우의 일별 값은 null(확인 불가)이다. 그 이후 0은 해당 날짜의 저장된
이벤트가 0개라는 뜻이며 완전한 과거 활동량을 보장하지 않는다.
UI에는 '저장된 로그인 기록 기준 · 수집 시작/완전성 미확인'을 표시해야 한다.
이 조건에서 연속적인 완전 집계 그래프를 주장하지 않는다.

새 텔레메트리·스키마·외부 분석·IP/기기 정보 수집은 없다.
운영 데이터의 보존/백필 현황은 아직 확인하지 않았다. 보존 정책이 확인되면
coverage 계약을 보강한다. 데이터량이 크면 event/created_at 인덱스의
필요성을 실제 실행 계획으로 검토하되 이 초안에는 마이그레이션이 없다.

## 검사와 현재 한계

- 타입 검사, 빌드, 변경 파일 ESLint 통과.
- 신규 단위 테스트 3개 통과 (범위, KST/결측 처리, 관리자 거부).
- 전체 테스트: 기준 262개 중 252 통과/7 실패, 변경 후 265개 중
  255 통과/7 실패. 양쪽 실패 목록 동일 (교재 데이터·Mac 경로 관련).
- 전체 ESLint 기준/변경 모두 기존 83개 오류. 새 파일 오류 없음.
- 임시 PGlite PostgreSQL 엔진에서 SQL 실행 검증 통과: KST 자정 경계, 동일 회원 반복, 기간 고유 회원 수, signup/미래 이벤트 제외, 7/30일, 기록 없음. 날짜 별칭 구문 오류를 이 검증에서 수정했다.
- 재현: API 빌드 후 `PGLITE_MODULE=/absolute/path/to/pglite node scripts/test-login-analytics-sql.mjs` (임시 QA 설치 사용; 운영 의존성 추가 없음). 실제 운영 DB 보존 범위 확인은 미실행.
- 원본 참고 이미지 libfile_41098d8594308191834fac0d0f90e346은 이 Mac에 저장/표시되지 않았다. 부모가 실제 원본을 보고 작성한 명시적 화면 설계로 별도 FE 구현과 합성 데이터 데스크톱/모바일 검증을 진행했다. 원본 대조 최종 검토는 부모 담당.
- 커밋은 부모 통합 검토용이다. 공유 원격 push·운영 배포·DB 변경 미실행.
