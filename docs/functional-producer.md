# Functional execution producer

Status: implemented offline and unit-tested; **not connected or production-qualified**. The original baseline CI and image-only workflow remain unchanged. The held functional workflow is inactive. No runner, credential, permission, secret, image deployment, database or network change is performed by these files.

`scripts/run-functional-evidence.cjs` executes six reviewed suites and creates a receipt only after every real process succeeds. Node commands use `shell:false`, explicit timeouts and sanitized environment variables. Counts come from the process TAP result. Missing summaries, failed subtests, skipped/todo cases, cancellation, timeouts and nonzero exits are rejected. Output records hashes, counts and matched case IDs rather than raw private test output. Required case IDs map to exact passed test titles in a committed, reviewed execution recipe; one genuine test may cover several IDs where its source asserts each behavior.

All API, frontend and deploy checkouts must match their explicit Git SHAs and have no tracked edits. The recipe contains only `{version:1,suites:[...]}` and is read from an `ops-prep/*.json` Git blob in the exact API commit. Runtime inputs separately provide the observed API SHA, pinned frontend/deploy SHAs, image identities and input hashes. There is no self-referential commit SHA embedded in its own recipe.

The CLI arguments are `reviewed-plan.json checkout-paths.json new-output.json`. The plan contains `version`, `definitionPath`, `suites`, and `bindings`. Each suite specifies its name, Node `steps:[{script,args,timeoutMs,checkout?}]`, and `caseTitles:{requiredCaseId:exactPassedTitle}`. Scripts must be tracked in the selected exact clean checkout. The default checkout is API for API/integration/migration/UI, FE for FE-unit, and deploy for controller. A committed `checkout:'api'` override permits an API-owned orchestrator to test another pinned checkout. Verified root paths, source SHAs and candidate image ID are explicitly injected as `HANQ_FUNCTIONAL_*` variables rather than expanded from arbitrary shell text. A real, reviewed six-suite recipe is still required; no placeholder recipe is executable by this change.

`scripts/run-functional-node-tests.cjs frontend ops-prep/fe-node-test-list.json` is the tracked API wrapper for existing FE plain-assert scripts. The committed list is read from the API Git blob; every test script must be tracked in the exact clean frontend SHA. It executes actual Node `--test` with TAP, so a plain script's assertion failure becomes a failed file test, and existing scripts need no FE changes. It does not install browser/dependency tools. The list and required runtime/browser environment must be supplied and reviewed before use. API integration likewise needs a tracked orchestrator for compilation and image execution; ignored compiled files cannot be used directly as executable recipe entries.

Bindings require `apiCommit`, `frontendCommit`, `deployCommit`, `imageId`, `imageConfigDigest`, `archiveSha256`, `composeSha256`, `bootstrapSha256`, `controllerSha256`, `databaseTarget:'hanq_final_20261028'`, and 54 `{version,checksum}` migrations. Roots specify `api`, `frontend`, `deploy`, and `inputs:{archive,compose,bootstrap,imageReceipt}` absolute file paths. The producer hashes the actual inputs, compares the controller's working bytes, reads committed LF SQL and validates the image-build receipt against the exact API/source/image/archive. These checks complement the controller's independent OCI archive and authenticated GitHub verification; they do not replace them.

`scripts/run-functional-migration.cjs <config.json>` adapts the already exercised synthetic PG17 restore test into a reusable TAP harness. Config specifies immutable `postgresImage`, `baselineImage`, `candidateImage`, exact `sourceCommit`, and an absolute `manifestFile`. The only accepted PG image is the existing reviewed PG17.11 digest. It creates its own labeled, unique isolated cluster and two `_test` databases, publishes no ports, uses no production connection/credentials, pulls no images, compares original schema54 and synthetic user/XP, restores a synthetic dump, checks idempotence and probes the old image. This portable adaptation has **not yet been executed**; the earlier concrete migration run is separate evidence. Its private loopback-only test cluster uses trust auth and is retained for diagnosis. It never accepts a database URL. Baseline/candidate image availability and Docker access are required.
